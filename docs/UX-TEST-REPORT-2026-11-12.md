## ข้อจำกัดของการทดสอบ (ต้องอ่านก่อนใช้ผล)
- **ไม่ได้กด "บันทึกใบขอเบิก" จริง** (production) → ไม่ได้ทดสอบ: หน้าสำเร็จ/เลขที่ใบเบิก, ผลฝั่ง server ต่อข้อมูลผิดปกติ, double-submit จริง
- **ไม่ได้ล็อกอินเจ้าหน้าที่/แอดมิน** → ไม่ได้ทดสอบหน้าอนุมัติ, จัดการพัสดุ, บัญชีพัสดุ, ผู้ใช้, สิทธิ์ของ POST endpoint ฝั่งเจ้าหน้าที่
- มือถือทดสอบด้วย emulation เท่านั้น (ไม่ใช่ iOS/Android จริง), ไม่ได้ทดสอบ screen reader, QR scan, ปุ่ม "+ เพิ่มประวัติผู้เบิก"

### ปัญหารองที่ไม่อยู่ใน Top 10
- Guest เห็นบล็อกผู้ใช้ "ผู้ขอเบิก" + ปุ่มออกจากระบบ (elder, newbie, impatient)
- "สังกัด" ตั้งค่าเริ่มต้นเป็น "สำนักงานศูนย์การศึกษา" ทั้งที่ required (newbie, elder)
- ไม่มี skip link, input ไม่ผูก label, ไม่จัดการ focus เมื่อเปลี่ยนหน้า SPA, ไม่มี aria-live, focus ring ของ input อ่อน (keyboard)
- หน้า "พัสดุหมด/ใกล้หมด": แสดงปุ่มเจ้าหน้าที่ให้ guest, ตารางกว้าง 680px เลื่อนแนวนอนบนมือถือ, คำว่า "จุดสั่งซื้อ" (elder, newbie)
- ข้อความ "ไม่พบข้อมูล" ไม่มีขั้นตอนถัดไป; วันที่แสดง ค.ศ. คู่กับ พ.ศ. (elder, newbie)
- ร่างฟอร์มเก็บข้อมูลส่วนบุคคลใน localStorage 30 นาที (breaker)
- Tailwind CDN runtime + HTML ~550KB (impatient)

## 3. ข้อที่ผ่านดี
- Guest เข้าฟอร์มได้ใน 1 คลิก; ไม่มี horizontal overflow ที่ 320–393px
- ไม่ลงชื่อ staff routes (#a-*, #t-my, #t-dash) เด้งกลับฟอร์ม; GET API ไม่ยืนยันตัวตน = 405; `/.env`, `/.git/config`, `/wrangler.toml`, ไฟล์ backup SQL = 404
- Input แปลก (HTML, emoji, SQL-like) ไม่ crash และแสดงเป็นข้อความธรรมดา
- จำนวนเกินสต็อกถูก clamp + toast; draft กู้คืนได้; ปุ่มค้นหารหัสบุคลากรกันกดซ้ำถูกต้อง
- SweetAlert: focus trap, Esc, คืนโฟกัสถูกต้อง; `lang="th"`, landmark, heading ครบ

## 3.1 ภาคผนวก: ตรวจฝั่งเจ้าหน้าที่ (admin ที่เจ้าของล็อกอินให้, อ่านอย่างเดียว)
ทำโดยเปิดเมนูทีละหน้าใน session เดียว (ไม่ใช่ Persona) — ไม่กดบันทึก/อนุมัติ/ลบ/ส่งใด ๆ ครอบคลุม 16 หน้า (แดชบอร์ด, ทะเบียนวัสดุ, บัญชีพัสดุ, จัดการพัสดุ, ร้านค้า, ใบสั่งซื้อ, ความเคลื่อนไหวสต็อก, Stock Card, จัดการรายการขอเบิก, ใกล้หมด, ของฉัน, Audit Log, ทะเบียนบุคลากร, ผู้ใช้, ตั้งค่า, โปรไฟล์)
- ไม่มี JS error/unhandled rejection ระหว่างเปลี่ยนหน้า; ไม่มี horizontal overflow (scrollWidth ≤ innerWidth ทุกหน้า ที่ viewport ~967px)
- **Touch target <44px เยอะมาก** (นับ control ที่มองเห็นในหน้า): จัดการพัสดุ 137/142, ตั้งค่าระบบ 51/60, ใบสั่งซื้อ 27/40, จัดการรายการขอเบิก 35/35, จัดการผู้ใช้ 20/20, ทะเบียนวัสดุ 12/13, บัญชีพัสดุ 11/13 → ผิดกฎ AGENTS.md ข้อ 2 ทั้งฝั่งเจ้าหน้าที่
- ตัวเลขปุ่มไอคอนไม่มี aria-label ที่สคริปต์ได้ **ไม่น่าเชื่อถือ** (เขียนเงื่อนไขผิด) จึงไม่นำมาใช้
- **ควรตรวจ (ยังไม่ยืนยัน):** แดชบอร์ดแสดง "วัสดุสำนักงาน 3,170 ชิ้น / 0 รายการ" และหมวดอื่น 0 ทั้งที่รวม 44 รายการ — จำนวนรายการต่อหมวดอาจนับผิด (ควรเทียบกับ `material_lots` ตาม AGENTS.md ข้อ 4)
