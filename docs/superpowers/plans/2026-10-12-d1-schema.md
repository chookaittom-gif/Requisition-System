# D1 Schema Plan — ระบบเบิกจ่ายพัสดุ (Phase 1 of the Cloudflare migration)

**Goal:** Define the Cloudflare D1 schema that replaces the Google Sheets tables, with constraints that close the legacy data-integrity gaps. Nothing is applied to the remote database in this phase.

**Inputs:** `Code/code.gs` (`HEADERS` at lines 29-53), `Code/index.html`, `docs/ระบบเบิกจ่ายพัสดุ.xlsx`, `ทะเบียนวัสดุคงเหลือ 2569.xls`.

**Decisions:**
- **Location:** the new project lives in `cloudflare/` next to `Code/`. The GAS code is not modified.
- **Primary keys:** the legacy ids (`U-…`, `M-…`, `R-…`) are the primary keys, so imports are idempotent upserts.
- **Scope:** inventory and schema only. No API, frontend or remote apply in this phase.

## Open decisions (block the next phases)
1. **Telegram bot token:** today an admin edits it in the Settings page. Moving it to a Worker secret removes that ability. Decide whether to keep it UI-editable (encrypted in D1) or secret-only.
2. **`PW_SALT`:** the real value must be copied from the Apps Script Script Properties into a Cloudflare secret. Without it, existing users cannot log in.
3. **Email delivery:** Workers have no `GmailApp`. Pick a provider (for example Gmail API with OAuth, or another mail API).
4. **Legacy `.xls` import:** material codes are empty and the fiscal years differ between sheets (2567/2568). The owner must approve a code format and the opening fiscal year.
5. **D1 `database_name`:** `wrangler.jsonc` uses `supply-db` as a placeholder. Confirm the real name in the dashboard before any `--remote` command.

## Next phases
1. Read-only check of the remote DB: `npx wrangler d1 execute DB --remote --command "SELECT name FROM sqlite_master WHERE type='table'"`
2. Back up the remote DB, then apply `0001_init.sql` remotely. This needs explicit approval.
3. Write and test the importer (Sheets export → D1) with `import_runs` counts.
4. Build the Worker API (auth, sessions, requests with atomic stock), then the frontend, then Drive resumable upload.
